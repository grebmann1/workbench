## The one behavior change

**skillsPanel**: before the sweep, pressing Tab inside the skill-body textarea inserted two spaces, trapping keyboard and screen-reader users in the editor. That was the only accessibility blocker that required a behavior change rather than additive ARIA. The fix:

1. Removed `handleContentKeydown` on the textarea — Tab now does native focus navigation.
2. Added a new `<div role="toolbar">` above the textarea with an **Insert indent** button labeled `aria-label="Insert indent (two spaces)"`.
3. Click handler `handleInsertIndent` reads the textarea's `selectionStart/End`, splices two spaces at the caret, updates tracked content, and re-focuses.

Users keep indentation functionality; everyone (including screen-reader / switch / voice users) can now escape the textarea.
