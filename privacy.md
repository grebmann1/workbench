# Privacy Policy for Workbench Extension

_Last updated: 2026-07-31_

The Workbench Extension is a Salesforce administration toolkit. Its core function is to establish direct communication between the user's web browser and Salesforce servers on behalf of the logged-in user, using the official Salesforce webservice APIs. The extension therefore only accesses the data and functionality already granted to the user within the Salesforce platform.

This policy discloses **all** data the extension collects, how that data is used, and every third party the data may be shared with.

## Salesforce data and authentication

- Every API call made by the Workbench Extension uses the access token/session already in use by the browser to connect with Salesforce.
- To obtain this token, the extension requires permission to read browser cookie information for Salesforce domains.
- Salesforce credentials, session tokens, and org data are used **only** to communicate with Salesforce servers on your behalf. They are not sent to Workbench-operated servers.
- On Workbench Desktop, imported refresh-token material is encrypted with OS-backed Electron safe storage.

## Usage analytics (Google Analytics)

The extension collects usage analytics and sends them to **Google Analytics** (Google LLC) via `https://www.google-analytics.com/mp/collect`. This collection is active by default.

Data sent to Google Analytics includes:

- A randomly generated client identifier and session identifier (not tied to your Salesforce identity).
- Page views, including the page title and page URL/location of the extension surface being used.
- Application usage events — the app opened, actions performed, and application names.
- Error events, including error messages generated by the extension.

This data is used to understand feature usage and diagnose errors so we can improve the product. It is shared with Google as the analytics processor and is subject to [Google's Privacy Policy](https://policies.google.com/privacy).

## AI features and third-party LLM providers

When you use the extension's optional AI agent / AI features, the content you submit — including your prompts and any code, metadata, or org content you include in a request — is transmitted to the third-party Large Language Model (LLM) provider **you configure**, using an API key or endpoint you supply.

Supported providers you may configure include:

- OpenAI (`api.openai.com`)
- Anthropic (`api.anthropic.com`)
- Google (Gemini / `generativelanguage.googleapis.com`)
- Mistral AI (`api.mistral.ai`)
- xAI (`api.x.ai`)
- A Salesforce-operated model gateway (for internal/enterprise use)

AI requests are sent directly from your browser/app to the provider you select. Data handling by that provider is governed by that provider's own privacy policy and terms. AI features are not used unless you invoke them. Review prompts before submitting sensitive code or content to an external AI model.

## Local storage

Some data is stored locally within your browser and/or on your device and is **not** transmitted to external parties. This includes:

- Metadata
- Org info
- Analytics client and session identifiers (described above)
- Virtual workspace files, which are stored in IndexedDB on your machine

Workbench does not automatically transfer your virtual file system contents to any server. Local workspace state stays on your machine unless you explicitly export or share it.

## Data retention

- Locally stored data remains on your device until you clear it (for example, by removing the extension's storage or uninstalling).
- Analytics data is retained by Google Analytics according to Google's retention settings and policies.
- Content sent to an AI provider is retained according to that provider's policies.

## Your choices

- You can avoid AI-related data sharing by not using the AI features.
- You can remove locally stored data at any time by clearing the extension's browser/app storage or uninstalling the extension.

## Verifying this policy

The Workbench Extension source code is available for inspection, and you can monitor your browser's network traffic to independently verify the data flows described here.
